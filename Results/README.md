# Results/

Provenance for every file in this directory. Read this before citing a number.

## `CrystalSystemRandomForestRegressorOptimizationStudy_Final.csv` (canonical)

Written by `FuelLatticeParameterModelOptimization.ipynb`. This is the per-crystal-system,
per-lattice-parameter-threshold optimization study for the Lumped RF model
(`RandomForestRegressor(n_estimators=600, random_state=42)`). Use this file for any
citation of the optimization study.

## `archive/`: retained for the record, not for citation

- **`CrystalSystemRandomForestRegressorOptimizationStudy_Full.csv`** has the same
  per-row `dataset_size` as `_Final.csv`, but **different** MSE/MAE/R² values (e.g.
  cubic @ 10 Å: MSE 0.166 in `_Final` vs 0.210 here). Two runs of what was intended to
  be the same configuration; the discrepancy was never resolved. Do not cite.
- **`CrystalSystemRandomForestRegressorOptimizationStudy.csv`**, the experimental-only
  dataset (cubic @ 10 Å: 4,174 rows vs 15,935 in `_Final`), i.e. theoretical Materials
  Project structures excluded.
- **`RandomForestRegressorOptimizationStudy.csv`**, an earlier schema using a
  `cubic_only` boolean column instead of `crystal_system`. Its `10,sg,TRUE` row matches
  the experimental CSV's cubic row exactly, suggesting it is an earlier export of the
  same experimental-only run.

## `metrics/ModelMetrics_CrossVal.csv`: the shipped models' own metrics

5-fold cross-validation metrics for all five models, generated by `python cli.py evaluate
--models rf1,rf2,gbr1,gbr2,lin`. **This file, not `_Final.csv`, is what the model cards and
`metrics.json` quote, and it is the source of Table 1 in the accompanying manuscript.** The
optimization study above explores a different dedup and feature configuration and does not
describe the shipped models' accuracy.

Note that these metrics describe the hyperparameters and the training frame rather than any
one fitted binary: `evaluate()` refits a fresh estimator per fold and never opens the files
in `Models/binaries/`.

## `metrics/cv_predictions/` : the values behind the figures

One file per model, each holding the out-of-fold prediction for all 64,128 training entries.
`DATA_DICTIONARY.md` describes the columns.

These files do not reduce exactly to `ModelMetrics_CrossVal.csv`. Recomputing `MSE_cubic`
from the points and comparing against the table gives:

| model | disagreement on `MSE_cubic` |
|---|---|
| `lin`, `gbr2` (a, b) | exact to machine precision |
| `rf2` | 3.5e-6 |
| `rf1` | 1.7e-5 |
| `gbr2` (c) | 3.1e-4 |
| `gbr1` | 2.2e-3 |

For every model but `gbr1` that is below the precision anything is reported to, and the
figures drawn from these points are the figures the table describes. For `gbr1` it is not.
Cite `ModelMetrics_CrossVal.csv`, and use these files for the point-level scatter behind
the figures rather than to recompute a `gbr1` aggregate.

## `metrics/feature_spearman_cubic.csv`

Spearman correlation of each of the 145 input features with the cubic-system lattice
parameter, written by `python scripts/feature_correlations.py`. All features appear, not
only those above the 0.2 threshold the published figure displays.

## `figures/`: committed plots

Actual-vs-predicted plots generated by `engine.reporting.plot_actual_vs_predicted()`
(from the core notebooks) and `engine.reporting.plot_pred_vs_true()` (from
`cli.py evaluate`). No notebook calls `savefig()` directly; all figure output goes through
the engine, so regenerating a figure is a single command.

## Notebook 4 dedup discrepancy

`FuelLatticeParameterModelOptimization.ipynb` dedups on
`("composition_reduced", "spacegroup_num")`, without `nsites`, via
`engine.optimize.DEDUP_KEYS_STUDY`. The training pipeline uses
`("composition_reduced", "spacegroup_num", "nsites")` (`engine.optimize.DEDUP_KEYS_TRAIN`,
matching `engine/train_models.py`). The difference is intentional: the study predates the
`nsites` addition to the dedup key, and the study's keys are what reproduce `_Final.csv`.
Changing the study to the training dedup keys would invalidate `_Final.csv`.
